# DSH 0.1.1-rc.2 迁移与后续协议边界

> 审阅日期：2026-08-30  
> 上一基线：`dsh-v0.1.0-rc.7`  
> 当前产品基线：npm 已发布的统一版本波次 `0.1.1-rc.2`  
> 已审阅但未接入：GitHub 源码 tag `dsh-v0.1.2-alpha.1`

## 1. 选择结果

催更姬当前升级到 `0.1.1-rc.2`，不直接 vendoring 或构建 alpha 源码。

原因不是 alpha “版本号较新但不够稳定”，而是它已经更换宿主协议；当前产品的
RPC、history、prompt 和 event stream 不能通过局部兼容继续工作。npm 的若干
子包 `latest` 标签仍可能指向旧版本，因此升级依据必须是与 CLI 相同的精确版本，
不能逐包采用 `latest`。

官方依据：

- [DeepSeek Harness 仓库](https://github.com/deepseek-ai/deepseek-harness)
- [已发布基线 dsh-v0.1.1-rc.2](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.1-rc.2)
- [已审阅源码 dsh-v0.1.2-alpha.1](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.2-alpha.1)
- [alpha Web 连接契约](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.2-alpha.1/packages/client/connection/README.zh.md)

## 2. rc.7 → rc.2 已识别的破坏点

| 变化 | 对催更姬的影响 | 当前处理 |
| --- | --- | --- |
| DSH 子包采用大量同版本 peer，npm 的默认标签不能表达统一波次 | 混装可能正常启动、到第一次 prompt 或工具调用才崩溃 | 所有直接依赖精确锁定；lockfile 内全部 DSH 包必须为 `0.1.1-rc.2` |
| LLM adapter 基础契约新增 `prepareCall` | 旧的第三方对象式 adapter 可能不再满足 ABI | 催更姬只组合 rc.2 官方 adapter；启动前检查自定义插件使用的 ABI 包 |
| `web_search` 参数由单个 `query` 调整为 `queries[]`，并增加查询数量配置 | 硬编码旧工具 schema 会失效 | 不复制官方 schema，交由同波次 `dsh-tool-web` 注册；真实插件流程测试覆盖工具加载 |
| `dsh web` 默认打开浏览器 | Electron 启动 Agent 会产生额外浏览器窗口 | supervisor 固定追加 `--no-open` |

## 3. 三层一致性门禁

1. `package.json`：自定义插件直接 import 的八个 ABI 包必须是精确
   `0.1.1-rc.2`，所有显式 DSH 依赖也不得跨版本。
2. `package-lock.json`：检查整个 DSH 闭包以及每个必需 peer 均存在且同版本。
3. 运行时：在派生 bin 路径、spawn 子进程前再次读取实际安装包版本；检查失败时
   Agent fail closed，不影响编辑器和其他业务模块。

命令：

```powershell
npm run dsh:compat
```

该命令已经接入 `architecture:check` 和 `prepackage:win`。

## 4. alpha.1 为什么不能半接入

alpha 的 ready URL 带一次性 `token`；Web 客户端先用它访问根路径并换取签名
cookie，随后 API 和 WebSocket 都依赖该 cookie。与此同时：

- Remote 路由从点号形式迁为斜线形式，请求体包成 `{ args }`；
- `session.history` 被 cursor 分页的 `session/page` 取代；
- 全局 `events.mux` 被 Remote multiplexing 和逐 session `session/follow` 取代；
- prompt 要求客户端生成 `requestId`；
- session 恢复、游标和断线重连必须作为一个协议整体迁移。

所以当前 supervisor 只接受严格的 `http://127.0.0.1:<port>` ready URL，看到
query/token 会明确拒绝。仅让页面能打开不等于 Agent 网关可用，也会制造错误的
“兼容 alpha”承诺。

## 5. 下一次升级的原子任务

只有 npm 发布与源码协议一致的稳定波次后，才执行以下同一批迁移：

1. 新建带 cookie jar 的本机认证 bootstrap，token 不进入 Renderer、日志或状态对象；
2. 用官方 Remote client 契约替换旧 `dsh-rpc-client`，不在业务层散落 URL 拼接；
3. 将 history、prompt、cancel 和 workspace/session 初始化整体迁移；
4. 用 `session/follow` 重写事件订阅、cursor 持久化、断线续传和去重；
5. 更新 fake wire、真实 DSH、Gateway、Electron 和 packaged E2E；
6. 最后才提高 `SUPPORTED_DSH_VERSION`，并整体重建 lockfile。

任何一步未完成都保持 rc.2，不增加双协议长期分支。
